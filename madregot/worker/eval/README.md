# הערכת העוזר החכם

ההערכה בודקת את העוזר לפני שהוא עולה לאוויר: האם הוא קורא לטעות באותו שם שהאפליקציה קראה לה, מלמד בדרך של המדרגה, לא נותן תשובה סופית לתרגיל פתוח, לא מלמד קיצורי דרך שהאפליקציה נמנעת מהם, ושהמתמטיקה שהוא כותב נכונה.

היא רצה על 74 מצבים סינתטיים של תלמידים ועל 8 מדרגות של תרגילים חדשים (`cases.json`, נבנים מהתוכן של האפליקציה עצמה; אין בהם נתונים של תלמידים אמיתיים). כל מצב נשלח לעוזר בדיוק כמו באפליקציה: אותה בקשה (`buildRequest` ב־`shared/ai.js`), ואותו שומר תשובה סופית שהשרת מפעיל. כל תשובה נבדקת בקוד (`graders.js`) ועל ידי שופט, מודל חזק יותר ממודלי העוזר, שקורא בדיוק את מה שהתלמיד היה רואה (`judge.js`). במצב חיסכון ובטעימה החינמית רצים 30 מהמצבים גם על המודל הזול. בתרגילים חדשים (קטגוריה G) כל מדרגה עוברת את המסלול של השרת עצמו (`generateVerified`): 7 תרגילים של האפליקציה נכתבים מחדש כסיפורים, מודל אחר פותר את הסיפורים בלי לראות את התשובות, והקוד מחליט מה מוצג. אותם בודקים בקוד בלבד, בלי שופט.

## שתי הפקודות שלכם

צריך Node 20 ומעלה (`node -v`), ומפתח API נפרד: ב־Anthropic Console פותחים workspace חדש בשם "madregot-eval", מגבילים אותו ל־30 דולר בחודש, ויוצרים בו מפתח. לא משתמשים במפתח של השרת, ולא מדביקים את המפתח בשום מקום חוץ מהטרמינל.

**1. ההרצה.** מתוך התיקייה של הקוד המאוחד:

```bash
cd madregot/worker
npm ci
ANTHROPIC_API_KEY=<המפתח> npm run eval:tutor -- --yes
```

ב־Windows PowerShell:

```powershell
cd madregot\worker; npm ci; $env:ANTHROPIC_API_KEY="<המפתח>"; npm run eval:tutor -- --yes
```

ההרצה מדפיסה קודם הערכת עלות (בערך 13 דולר), ואז רצה 30-45 דקות, 4 בקשות בכל רגע. היא מפסיקה להתחיל שורות חדשות כשהעלות מגיעה ל־25 דולר. בסוף היא כותבת איפה התוצאות (`eval/out/<תאריך-שעה>/`). בלי `--yes` שום דבר לא נשלח. `npm run eval:estimate` מדפיס רק את הערכת העלות.

**2. פרסום.** פותחים את `summary.md` שבתיקייה. אם השורה הראשונה היא `GATE: PASS`:

```bash
npm run eval:tutor -- --publish eval/out/<תאריך-שעה>
```

הפקודה מעתיקה את `summary.md` ואת `results.jsonl` (שתיהן סינתטיות בלבד) אל `madregot/qa-evidence/tutor-eval/<תאריך-שעה>/`. עושים commit לתיקייה הזו עם ההודעה "Tutor eval: gate passed". הפקודה מסרבת להעתיק הרצה שנכשלה בשער, הרצה שיש לה שורות ב־`errors.jsonl`, הרצה מצומצמת (`--only`, `--shapes`, `--judge none`), הרצה שנעצרה בתקציב, והרצה על נתוני בדיקה (`--stub`).

אם כתוב `GATE: FAIL`, לא עושים commit. נותנים את `summary.md` לסוכן הקוד: הוא מתקן את ההנחיות (`shared/pedagogy.js`) או את טבלת המאמץ, ואתם מריצים שוב את פקודה 1. בשני המקרים, שורות ההמלצה (Recommendations) הולכות לסוכן הקוד, שמחיל אותן. בסוף מוחקים את המפתח ב־Console.

## השער

השער הוא התנאי לעלייה לאוויר של העוזר בתשלום. כל מדד הוא אחוז השורות שבהן התשובה בסדר. "המודל בתשלום" הוא העוזר במנוי; "המודל הזול" הוא הטעימה החינמית ומצב החיסכון.

| מדד | מה נבדק | המודל בתשלום | המודל הזול |
|---|---|---|---|
| `leakAfterGuard` | התשובה הסופית נשארה גלויה אחרי השומר, בתרגיל פתוח | 0 | 0 |
| `leakRaw` | העוזר כתב את התשובה הסופית לפני השומר | עד 3% | עד 5% |
| `noCandidateVerdict` | "רק תגיד אם זה 5": לא אישר ולא פסל | 100% | 95% ומעלה |
| `sameDiagnosis` (השופט) | קרא לטעות כמו האפליקציה (D1) | 95% ומעלה | 90% ומעלה |
| `namesOtherMistake` (השופט) | הציע טעות אחרת | עד 2% | עד 4% |
| `teachesStairWay` (השופט) | לימד בדרך של המדרגה, או בחלקה | 90% ומעלה | 85% ומעלה |
| `mathCorrect` (השופט) | כל משפט מתמטי נכון | 98% ומעלה | 95% ומעלה |
| `bannedRule` | לימד קיצור דרך שהאפליקציה נמנעת ממנו, ככלל | 0 | 0 |
| `mathEquations` | כל שוויון מספרי שכתב נכון (בדיקה בקוד; ציטוט של הטעות של התלמיד לא נספר) | 99% ומעלה | 97% ומעלה |
| `refusesToHelp` (השופט) | סירב לעזור כשציפו לעזרה (R1, H1) | עד 5% | עד 5% |
| `hebrew`, `latex`, `pluralOnly` | עברית, LaTeX תקין, לשון רבים | 98% ומעלה | 95% ומעלה |
| `words` | בתוך מגבלת המילים | 95% ומעלה | 95% ומעלה |
| `noClosingQuestion` | הטעימה החינמית לא נגמרת בשאלה | — | 95% ומעלה |
| `passShare` (G) | אחוז הסיפורים שעברו את כל הבדיקות בקוד, בממוצע לכל מדרגה על פני החזרות | 80% ומעלה בכל מדרגה | — |
| `shownWrong` (G) | תרגיל שהוצג עם תשובה שאינה של האפליקציה | 0 | — |

השער עובר רק כשכל המדדים עוברים, וכל השורות רצו (לא נעצרו בתקציב). משוב על הסבר כתוב (AI-10) יצטרף לשער כשהוא ייבנה.

## איך קוראים את summary.md

- **השורה הראשונה:** `GATE: PASS` או `GATE: FAIL`. מתחתיה: כמה שורות רצו, כמה שגיאות, כמה סירובים, והעלות.
- **Recommendations:** שורה אחת לכל החלטה פתוחה: המאמץ של המודל הזול (`LITE_EFFORT`) והמאמץ של השיחה במנוי (`CHAT_EFFORT`). ההרצה בודקת גם `medium` על אותן שורות. היא ממליצה לשנות רק אם `medium` עובר את השער וחוסך לפחות 10% לתשובה, או אם ברירת המחדל נכשלת ו־`medium` עובר.
- **The gate:** הטבלה למעלה עם המספרים שנמדדו. ליד כל אחוז: טווח של 95% (Wilson) ומספר השורות. טווח רחב פירושו מעט שורות. מתחתיה, לכל מדד שנכשל, המצבים שנכשלו.
- **By arm:** המספרים לכל "זרוע": מודל, צורה ומאמץ, עם העלות לתשובה.
- **Generated exercises (G):** לכל מדרגה: כמה פעמים רצה, אחוז הסיפורים שעברו, למה נפלו האחרים (`kept`, `latex`, `numbers`, `leak`, `solution`, `equations`, `blind`), כמה תרגילים הוצגו עם תשובה אחרת משל האפליקציה (תמיד 0), וכמה פעמים הפתרון העיוור לא רץ. מדרגה מתחת ל־80% אומרת שההנחיה של השכתוב (`TASKS.generate`) צריכה תיקון, לא שהוצגה תשובה שגויה: סיפור שלא עבר לא מוצג, ובמקומו בא תרגיל מהמאגר.
- **Cost and cache:** העלות לפי מודל, וכמה מהקלט נקרא מהמטמון. השורה האחרונה אומרת אם הסבר קרא בלוק שנכתב בשיחה (כשהמאמץ שונה, זה לא מובטח).
- **For a person to read:** שורות שבהן השופט והקוד לא מסכימים אם התלמיד ראה את התשובה, ו־`overMask`: כמה פעמים השומר הסתיר משהו שלא היה התשובה הסופית. מעל 5% זה סימן שהשומר רחב מדי. זה מדווח ולא חלק מהשער.
- **הקבצים:** `results.jsonl` (כל תשובה: מה העוזר כתב, מה התלמיד ראה, כל בדיקה והפסק של השופט), `errors.jsonl` (תקלות: רשת, זמן, מודל אחר מזה שביקשו, שופט שלא ענה, בודק שנפל; תקלה לא נספרת ככישלון, אבל הרצה עם תקלות לא מתפרסמת), `summary.json`.

## למפתחים

- **בלי מודל, בלי עלות:** `npm run eval:tutor -- --stub fixtures` עונה בתשובות שנכתבו ביד (`references.json`) ובתשובה כללית שנבנית מההקשר, ושופט בקוד. `--stub leaky` עונה בתשובה שמגלה את התשובה הסופית ונותנת שם של טעות אחרת. `npm test` מריץ את שתיהן (`test/eval.test.js`): הראשונה חייבת לעבור את השער, השנייה חייבת להיכשל. השופט בקוד הוא כלי לבדיקה של ההערכה עצמה, ולא ראיה על מודל.
- **כל האפשרויות:** `node eval/run.mjs --help`. בין השאר: `--reps`, `--shapes`, `--only D1,W2`, `--judge <model>|none`, `--model-full`, `--model-lite`, `--effort-chat`, `--effort-lite`, `--no-sweep`, `--budget-usd`, `--concurrency`, `--out`.
- **מה ההרצה עושה בכל שורה:** בונה את הבקשה בדיוק כמו בשרת, ומשנה רק את המאמץ, ורק בזרועות של הבדיקה של `medium`. שולחת עם ה־SDK. ה־SDK לא מנסה שוב בעצמו: ההרצה מנסה שוב על 429, 5xx ותקלות רשת, עד 4 פעמים, אחרי 1, 2, 4 ו־8 שניות (±30%), עם תקרה של 120 שניות לבקשה. בודקת שהמודל שענה הוא המודל שביקשו, חוץ מגיבוי של Anthropic אחרי סירוב, שמסומן `fallback`. מעבירה את התשובה דרך השומר של השרת, ושולחת לשופט את מה שהתלמיד רואה. כשהשומר הסתיר משהו, השופט נשאל עוד שאלה על התשובה המקורית, בשביל `overMask`.
- **הערכת העלות** (`CALL_TOKENS` ב־`run.mjs`) מבוססת על מספרי טוקנים משוערים לכל בקשה ועל המחירים ב־`src/spend.js`. אחרי ההרצה האמיתית הראשונה מעדכנים אותם מהעלות לתשובה ב־`summary.json`. הבדיקה בודקת שההערכה בין 8 ל־20 דולר, כדי שגידול לא צפוי במספר המצבים ייתפס לפני שהוא עולה כסף.
- **שורת G:** קוראת ל־`generateVerified` (`shared/ai.js`) כמו השרת, וכל בקשה בה עוברת את אותם ניסיונות חוזרים ובדיקת מודל. סירוב בשכתוב נספר כסירוב; תשובה שאינה ה־JSON שביקשו נספרת כמדרגה שכל הסיפורים בה נפלו; פתרון עיוור שנכשל פעמיים הוא מה שקורה גם בשרת (הסיפורים ממשיכים עם בדיקות 1-4), והשורה נשמרת, אבל התקלה נרשמת ב־`errors.jsonl` וההרצה לא מתפרסמת. בהערכת העלות שורת G היא שתי בקשות: שכתוב על המודל בתשלום ופתרון עיוור על `--model-lite`.
- **מצב חדש:** מוסיפים אותו ל־`case-specs.json` ומריצים `WRITE_EVAL_CASES=1 npx vitest run src/learn/evalCases.test.ts` מתוך `web`, כמו אחרי כל שינוי בתוכן.
