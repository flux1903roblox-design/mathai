# המנוי לעוזר החכם: מדריך לבעלים

המסמך הזה מיועד לבעלים של מדרגות. הוא מסביר מה השרת עושה, איך מפעילים את המנוי בזהירות, ואיך מטפלים במנויים בלי ממשק ניהול באינטרנט.
שום דבר כאן לא הופעל בשרת האמיתי. כל צעד שמסומן "בשרת" הוא שינוי בייצור, ואתם מריצים אותו.

## המתג: `AI_PAYWALL`

- `AI_PAYWALL = "off"` (ברירת המחדל). הפריסה לא משנה כלום למשתמשים: תלמיד בכיתה מקבל 40 פעולות ביום (`AI_DAILY_LIMIT`), מורה 200 (`TEACHER_DAILY_LIMIT`), ותלמידים בלי כיתה 20 ביום לכל רשת (`SOLO_DAILY_LIMIT`). הכניסה במייל, ספק התשלום לבדיקה והסקריפט של הבעלים עובדים, כדי שאפשר יהיה לעשות חזרה. תשלום באתר עונה `paywall_off`.
- `AI_PAYWALL = "on"` מפעיל את המנוי. חזרה אחורה: משנים ל־`"off"` ופורסים.
- **חלון מעבר לכיתות קיימות.** `BILLING_START` ו־`LEGACY_CLASS_AI_UNTIL` (תאריכים `YYYY-MM-DD`). כיתה שנוצרה לפני `BILLING_START` ואין לה רישיון שומרת על 40 ו־200 ביום עד סוף `LEGACY_CLASS_AI_UNTIL`, עם תקרה כיתתית של 600 יחידות ביום. כיתה חדשה אף פעם לא נכנסת לחלון הזה.

## מה כל אחד מקבל כשהמתג פועל

| | שיחה והסבר | בדיקת דף | תרגילים חדשים | בדיקת מבחן | מודל |
|---|---|---|---|---|---|
| חינם (כל מכשיר, תלמיד או מורה בלי רישיון) | 2 ביום (מורה: 5) | לא | לא | לא | `FREE_MODEL` (ריק = `claude-haiku-5-5`), תשובה קצרה |
| מנוי משפחתי (עד 3 מכשירים, מכסה משותפת) | 30 | 6 | 5 | 2 (עד 10 בחודש) | `CLAUDE_MODEL` |
| רישיון כיתה, לכל תלמיד | 20 | 3 | 3 | 1 | `CLAUDE_MODEL` |
| מורה בכיתה עם רישיון | 100 | 20 | 30 | 20 | `CLAUDE_MODEL` |
| ניסיון לכיתה (רק באישור שלכם, 14 יום, עד 40 מקומות) | 10 (מורה 50) | 2 (מורה 10) | לא | לא | `CLAUDE_MODEL` |

השיעורים, המפה, המשימות ומדי פתוחים לכולם תמיד. רק העוזר החכם מוגבל.

תקרות שמגינות על העלות:
- חינם: עד 80 שאלות ביום לכל רשת, רק למכשירים אנונימיים (`FREE_NET_DAILY`); עד 80 לכל כיתה בלי רישיון (`FREE_CLASS_DAILY`); עד 3000 בסך הכול (`FREE_GLOBAL_DAILY`); והטעימה נעצרת להיום כשהעלות שלה מגיעה ל־`FREE_DAILY_BUDGET_USD` (5$).
- רישיון כיתה: תקרה כיתתית של מספר המקומות כפול 25 יחידות ביום (שיחה 1, בדיקת דף 4, תרגילים 3, מבחן 20). זה עוצר קוד כיתה שדלף.
- שימוש הוגן: מנוי משפחתי שעבר `FAMILY_MONTHLY_BUDGET_USD` (5$) בחודש, או כיתה שעברה מקומות כפול `CLASS_SEAT_MONTHLY_BUDGET_USD` (0.8$), עובר עד ה־1 בחודש לשיחה בגרסה קצרה, ובדיקות הצילום, המבחן והתרגילים נחות.
- ניסיון לכיתה נעצר להיום כשהעלות של כל הניסיונות מגיעה ל־`TRIAL_DAILY_BUDGET_USD` (10$).
- כשהעלות של כל היום עוברת `OWNER_ALERT_USD` (20$), נשלח אליכם מייל אחד.
- שאלה שנכשלה (שגיאה בשרת של Claude, תשובה שבורה או סירוב) לא נספרת. כדי שלולאה של סירובים לא תעלה כסף, יש גם מונה ניסיונות שלא מתאפס (פי 3 מהמכסה).
- הגיבוי האחרון: מגבלת ההוצאה של ה־workspace בלוח של Anthropic. הגדירו אותה.

כל מגבלה אפשר לשנות במשתנה שלה, ואת כל השאר ב־`AI_LIMITS` (JSON), לפי `worker/src/entitle.js`.

## הפעלה, צעד אחר צעד

כל הפקודות מהתיקייה `madregot/worker`.

1. **סודות** (בשרת). כל אחד נוצר עם `openssl rand -hex 32` ונשמר עם `npx wrangler secret put <שם>`:
   `AUTH_SECRET`, `IP_HASH_SECRET`, `WEBHOOK_PATH_SECRET`. ובנוסף `ANTHROPIC_API_KEY` ו־`RESEND_API_KEY`.
   אם הגדרתם בעבר `ADMIN_KEY`, מחקו אותו: `npx wrangler secret delete ADMIN_KEY`. אין יותר ממשק ניהול באינטרנט.
2. **מסד הנתונים** (בשרת). שינויים במסד הנתונים עוברים רק דרך `worker/migrations`; לא מריצים יותר את `schema.sql` על מסד אמיתי.
   ```bash
   npm run db:migrate:local      # במחשב שלכם, לבדיקה
   npm run db:migrate            # בשרת
   ```
   המיגרציה `0001` מוחקת את חמש הטבלאות של הגרסה הקודמת, שלא הופעלה אף פעם, ואת המונים שהחזיקו כתובות רשת. זה בטוח רק לפני הפעלת המתג בפעם הראשונה.
3. **משתנים** ב־`wrangler.toml`: `PUBLIC_URL`, פרטי העסק (`BUSINESS_NAME`, `BUSINESS_ID`, `BUSINESS_ADDRESS`, `CONTACT_EMAIL`, `CONTACT_PHONE`), `OWNER_EMAIL`, `EMAIL_FROM`, המחירים (`PRICE_FAMILY_MONTH_AGOROT`, `PRICE_FAMILY_YEAR_AGOROT`, `PRICE_CLASS_SEAT_YEAR_AGOROT`, באגורות, כולל מע״מ), `VAT_MODE` (`included`, או `exempt` לעוסק פטור), `TERMS_VERSION`, והתאריכים `BILLING_START` ו־`LEGACY_CLASS_AI_UNTIL`.
4. **פריסה עם המתג כבוי** (בשרת): `npx wrangler deploy`.
5. **חזרה על כל התהליך** ב־Worker של תצוגה מקדימה עם `BILLING_PROVIDER="test"`, `BILLING_MODE="test"`, `ALLOW_TEST_BILLING="true"`, `AI_PAYWALL="on"`, והסוד `TEST_WEBHOOK_SECRET` (רק שם, או ב־`.dev.vars` במחשב). דף התשלום לבדיקה הוא `/api/billing/test-pay/<הזמנה>`, עם כפתור "תשלום מוצלח" וכפתור "תשלום שנכשל". שום כרטיס לא מחויב, ומנוי שנוצר במצב בדיקה לא יכול לפעול במצב אמיתי.
6. **מייל למורים** על התאריך, ורישיונות פתיחה לכיתות שצריכות (ראו "הסקריפט של הבעלים").
7. **הפעלה** (בשרת): `AI_PAYWALL="on"` ופריסה. אחרי שבוע: `npm run owner -- usage --from <תאריך> --to <תאריך>`, ולפי זה מכווננים מחירים ותקציבים.

## תשלום

- `BILLING_PROVIDER = "manual"` (עכשיו). אין תשלום באתר. אתם גובים בדרך שנוחה לכם ופותחים את המנוי בסקריפט. הצטרפות באתר נפתחת רק עם ספק שיש לו גם ביטול דרך API, כדי שביטול באתר תמיד יעצור את החיוב.
- ספק אמיתי (Grow, ‏Cardcom, ‏PayPlus או Paddle) מתווסף ב־`worker/src/providers/` כשתבחרו. ההודעה (webhook) מגיעה אל `/api/billing/webhook/<ספק>/<WEBHOOK_PATH_SECRET>`; השרת לא סומך על תוכן ההודעה, אלא מושך את מצב העסקה מהספק, ובודק שהסכום, המטבע והמצב (בדיקה או אמיתי) תואמים להזמנה שנוצרה בשרת. סכום שלא תואם לא פותח מנוי, ואתם מקבלים מייל.
- ביטול תופס מהרגע שההורה ביקש, גם אם הספק לא זמין. השרת מנסה שוב כל שעה, ואחרי 24 שעות בלי אישור מהספק אתם מקבלים מייל. חיוב שמגיע אחרי הביטול מוחזר אוטומטית.
- ב־14 הימים הראשונים ביטול מחזיר את כל הסכום. במנוי שנתי אחרי 14 יום אפשר החזר יחסי. ספק בלי API להחזרים: ההחזר נרשם בתור, ואתם מקבלים מייל לבצע אותו בלוח של הספק.
- חיוב שבוטל בכרטיס (chargeback) מסיים את המנוי ומקפיא את החשבון לתשלומים חדשים, עד שאתם משחררים אותו.

## הסקריפט של הבעלים

אין ממשק ניהול באינטרנט. כל פעולה רצה מהמחשב שלכם דרך wrangler, ונרשמת ב־`audit_log`. בלי `--local` הפקודה רצה על המסד בשרת.

```bash
npm run owner -- grant-class --class ABC234 --until 2027-08-31 --seats 35 --invoice 1042 --note "pilot"
npm run owner -- grant-class --class ABC234 --seats 30 --trial          # ניסיון של 14 יום
npm run owner -- grant-school --classes 5 --seats 35 --until 2027-08-31 --invoice 1043   # מדפיס קוד רישיון פעם אחת
npm run owner -- grant-family --email parent@example.com --until 2027-01-31
npm run owner -- cancel --id <מזהה מנוי> --mode period_end             # ביטול שהגיע במייל או בטלפון
npm run owner -- refund --id <מזהה מנוי> [--agorot 1500]
npm run owner -- end --id <מזהה מנוי>
npm run owner -- clear-hold --email parent@example.com
npm run owner -- forget --email parent@example.com                    # מחיקת חשבון לבקשת הורה
npm run owner -- list --status active
npm run owner -- events --outcome mismatch
```

תאריך פירושו סוף אותו יום בשעון ישראל. הערות נשמרות רק עם אותיות, ספרות, רווחים ו־`.,-/`.

## פרטיות

- השרת שומר רק את כתובת המייל של מי שנכנס. כתובת שביקשה קוד ולא נכנסה לא נשמרת (נשמר רק HMAC שלה).
- כתובות רשת לא נשמרות. המונים לפי רשת משתמשים ב־HMAC עם `IP_HASH_SECRET`.
- השרת לא שומר את השיחות עם העוזר. הוא שומר מונים יומיים ואת העלות של כל יום.
- פרטי כרטיס לא עוברים דרך השרת. ברשומות התשלום יש סכום, תאריך וקישור לחשבונית של הספק.
- הורה יכול להוריד את הנתונים שלו (`/api/account/export`) ולמחוק את החשבון. מחיקה דורשת קוד מהמייל מ־10 הדקות האחרונות.

## איפה זה בקוד
